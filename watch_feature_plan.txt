FilmCOCK! 영화 상세 및 시청 경로 기능 계획서
================================================

문서 목적
---------
첨부된 영화 상세 화면 이미지를 기준으로, 현재 앱에 없는 "보러가기" 기능과 OTT/극장 시청 경로를 어떤 순서로 추가할지 정리한다.
이 문서는 구현 전 설계·검토용이며, 현재 단계에서는 코드에 적용하지 않는다.

현재 상태 추론
--------------
[x] 홈에서 영화를 누르면 MovieDetailScreen으로 이동한다.
[x] 영화 상세 상단 배경 이미지와 예고편 재생 버튼이 존재한다.
[x] 영화 제목, 개봉일, 평점, 장르, 줄거리, 주요 출연진, 추천 영화 영역이 존재한다.
[x] 예고편은 TMDB videos API의 YouTube Trailer/Teaser 데이터를 사용한다.
[ ] 영화 상세 화면에 보러가기 버튼은 아직 없다.
[ ] OTT 제공 서비스 조회 API는 아직 없다.
[ ] 극장 상영 정보 조회 API는 아직 없다.
[ ] OTT/극장 선택 하단 시트는 아직 없다.
[ ] 서비스 아이콘 클릭 후 외부 링크로 이동하는 기능은 아직 없다.
[ ] 좋아요, 봤어요, 댓글, 공유 액션은 화면 디자인만큼 완성되지 않았다.

첨부 이미지에서 추론한 최종 사용자 흐름
---------------------------------------
[ ] 사용자가 홈에서 영화 포스터를 누른다.
[ ] 영화 상세 화면으로 이동한다.
[ ] 제목·개봉일·평점·장르 아래에 "보러가기" 버튼을 표시한다.
[ ] 사용자가 "보러가기" 버튼을 누른다.
[ ] 화면 아래에서 Bottom Sheet가 올라온다.
[ ] Bottom Sheet 제목은 "어디서 볼까요?"로 표시한다.
[ ] Bottom Sheet 상단에 "OTT"와 "극장" 탭을 표시한다.
[ ] OTT 탭을 기본 선택 상태로 연다.
[ ] 현재 영화의 국내 OTT 서비스 목록을 조회한다.
[ ] 서비스별 로고와 서비스명을 표시한다.
[ ] 서비스 아이콘을 누르면 해당 영화의 시청 또는 상세 페이지로 이동한다.
[ ] 극장 탭을 누르면 국내 극장 상영 정보 또는 예매 경로를 표시한다.
[ ] 데이터가 없으면 빈 상태 메시지를 표시한다.
[ ] 로딩 중에는 로딩 표시를 보여준다.
[ ] API 오류가 발생하면 재시도 가능한 오류 상태를 보여준다.
[ ] 아래로 내리거나 바깥 영역을 누르면 Bottom Sheet를 닫을 수 있다.

1. 영화 상세 화면 UI 추가
-------------------------
[ ] 대상 파일: lib/presentation/screens/detail/movie_detail_screen.dart
[ ] 현재 영화 정보 영역에서 장르 목록 아래 위치를 기준으로 보러가기 버튼을 추가한다.
[ ] 버튼은 첨부 이미지처럼 상세 정보의 주요 행동으로 보이도록 전체 폭에 가깝게 배치한다.
[ ] 버튼 문구는 "보러가기"로 통일한다.
[ ] 버튼 클릭 시 현재 Movie 객체의 id를 시청 정보 조회 함수에 전달한다.
[ ] 영화 제목이 길어져도 버튼 크기나 주변 레이아웃이 깨지지 않게 한다.
[ ] 장르가 여러 개일 때도 보러가기 버튼이 줄거리 영역과 겹치지 않게 한다.
[ ] 상세 데이터 로딩 전에는 버튼을 숨기거나 초기 영화 객체 기준으로 동작하게 할지 결정한다.
[ ] 상세 API 실패 시에도 이미 전달받은 영화 id를 이용해 보러가기 기능을 사용할 수 있게 한다.
[ ] 예고편 재생 버튼과 보러가기 버튼의 역할을 명확히 분리한다.
[ ] 예고편 버튼은 영상 재생, 보러가기는 실제 시청 서비스 선택으로 동작시킨다.

2. 시청 서비스 데이터 모델 설계
--------------------------------
[ ] 대상 후보 파일: lib/data/models/movie_model.dart 또는 별도 watch_provider_model.dart
[ ] 영화별 시청 서비스 정보를 담는 모델을 추가한다.
[ ] 서비스 식별자(providerId)를 저장한다.
[ ] 서비스 표시명(providerName)을 저장한다.
[ ] 서비스 로고 이미지 경로 또는 URL(providerLogoPath)을 저장한다.
[ ] 외부 이동 링크(link)를 저장한다.
[ ] 서비스 이용 방식(type)을 저장한다.
[ ] 이용 방식은 구독(subscription), 광고(free), 대여(rent), 구매(buy)로 구분할 수 있게 한다.
[ ] 국가 코드(countryCode)를 저장하거나 API 요청 단계에서 KR로 고정한다.
[ ] OTT와 극장 정보를 구분할 수 있는 category 필드를 둔다.
[ ] API 응답에 일부 필드가 없을 때 null 또는 빈 문자열을 안전하게 처리한다.
[ ] 로고가 없을 경우 기본 영화 아이콘 또는 회색 placeholder를 사용한다.

3. OTT API 연동
----------------
[ ] 우선 TMDB Watch Providers API 사용 가능 여부를 확인한다.
[ ] 요청 경로는 영화 id 기준 watch/providers 엔드포인트로 설계한다.
[ ] 국가 코드는 대한민국 KR 기준으로 처리한다.
[ ] TMDB API 키는 기존 ApiSecrets 사용 방식을 유지한다.
[ ] API 호출 위치는 기존 ApiService에 추가한다.
[ ] 함수 예시: getMovieWatchProviders(int movieId)
[ ] 응답의 KR 영역을 우선 읽는다.
[ ] flatrate 데이터는 구독형 OTT로 변환한다.
[ ] free 데이터는 무료/광고형 서비스로 변환한다.
[ ] rent 데이터는 대여 서비스로 변환한다.
[ ] buy 데이터는 구매 서비스로 변환한다.
[ ] provider_name은 사용자 화면의 서비스 이름으로 사용한다.
[ ] logo_path는 TMDB 이미지 URL로 완성한다.
[ ] link는 TMDB watch link를 기본 외부 링크로 사용한다.
[ ] provider 순서는 API가 반환한 순서를 우선 유지한다.
[ ] 동일 provider가 여러 분류에 중복되면 화면에서 중복 노출하지 않을지 결정한다.
[ ] 같은 서비스가 구독과 대여에 동시에 있을 때 이용 방식 라벨로 구분할지 결정한다.
[ ] 응답이 비어 있으면 "현재 국내 OTT 제공 정보를 찾을 수 없습니다."를 표시한다.
[ ] 401, 404, 429, 네트워크 오류를 일반 오류로 안전하게 변환한다.
[ ] API 키가 노출되는 현재 구조의 보안 위험은 별도 개선 항목으로 기록한다.

4. 극장 정보 설계
------------------
[ ] TMDB Watch Providers만으로 극장 상영 정보를 완전히 제공할 수 있는지 확인한다.
[ ] 극장 정보가 부족하면 KOBIS API 사용 가능성을 검토한다.
[ ] KOBIS에서 영화명 검색 또는 영화 코드 매핑이 필요한지 확인한다.
[ ] 현재 앱의 KOBIS 영화 데이터와 TMDB 영화 id 사이 매핑 전략을 결정한다.
[ ] 현재 상영 중인지 판정할 기준 날짜를 정의한다.
[ ] 극장 정보가 실제 상영관 단위로 제공되지 않으면 예매 링크 중심으로 단순화한다.
[ ] 국내 상영 정보가 없을 때 OTT 탭과 동일한 빈 상태 처리를 적용한다.
[ ] 극장 탭이 데이터 없이 항상 빈 화면이 되지 않도록 사용자 안내 문구를 준비한다.
[ ] 극장 예매 링크가 없으면 버튼을 비활성화한다.

5. Bottom Sheet UI 구현
-----------------------
[ ] 대상 파일: 새 watch_options_sheet.dart 또는 movie_detail_screen.dart 내부 위젯
[ ] showModalBottomSheet를 사용해 화면 하단에서 올라오게 한다.
[ ] 배경은 첨부 이미지처럼 어두운 색으로 구성한다.
[ ] 모서리는 상단만 둥글게 처리한다.
[ ] 상단에 드래그 핸들을 표시한다.
[ ] 제목은 "어디서 볼까요?"로 표시한다.
[ ] OTT와 극장 탭을 TabBar 또는 직접 만든 탭 컨트롤로 배치한다.
[ ] OTT를 기본 탭으로 선택한다.
[ ] 선택된 탭은 보라색 포인트 색상으로 표시한다.
[ ] 선택되지 않은 탭은 회색 계열로 표시한다.
[ ] 탭 아래에 구분선을 표시한다.
[ ] 서비스 목록은 첨부 이미지처럼 아이콘 중심의 가로 또는 격자 형태로 표시한다.
[ ] 서비스 아이콘은 고정 크기로 배치해 로딩 전후 레이아웃이 흔들리지 않게 한다.
[ ] 서비스명은 아이콘 아래 또는 아이콘 옆에 표시한다.
[ ] 긴 서비스명은 줄바꿈 또는 말줄임표로 처리한다.
[ ] 서비스 목록이 많아도 Bottom Sheet 내부에서 스크롤 가능하게 한다.
[ ] Bottom Sheet 높이는 콘텐츠에 따라 커지되 화면 전체를 가리지 않도록 제한한다.
[ ] 뒤로가기 버튼과 바깥 영역 터치로 닫을 수 있게 한다.

6. OTT 서비스 아이콘 처리
--------------------------
[ ] TMDB provider logo URL을 사용하는 방식을 우선 검토한다.
[ ] Google Play 아이콘처럼 별도 자산이 필요한 서비스는 assets/images에 추가한다.
[ ] 서비스 아이콘이 네트워크에서 실패하면 placeholder를 표시한다.
[ ] 아이콘 자체를 서비스 공식 로고와 혼동하지 않도록 이름도 함께 표시한다.
[ ] Google Play, Netflix, Disney+, Apple TV, Watcha 등 API 반환 서비스에 대응한다.
[ ] 실제 API가 반환하지 않은 서비스를 임의로 고정 노출하지 않는다.
[ ] 이미지 저작권 및 서비스 로고 사용 범위를 확인한다.

7. 외부 링크 이동
------------------
[ ] url_launcher 패키지 사용 여부를 검토한다.
[ ] 현재 pubspec.yaml에 url_launcher가 없으면 의존성 추가를 검토한다.
[ ] 링크 클릭 시 canLaunchUrl 검사를 수행한다.
[ ] 앱에서 열 수 없으면 외부 브라우저로 여는 fallback을 둔다.
[ ] 링크가 null이거나 비어 있으면 클릭을 막고 안내한다.
[ ] 사용자가 서비스를 선택한 뒤 Bottom Sheet를 닫을지 유지할지 결정한다.
[ ] 외부 브라우저 복귀 후 상세 화면 상태가 유지되는지 확인한다.
[ ] Android와 iOS에서 http/https 링크 정책을 확인한다.

8. 영화 상세 액션 영역
----------------------
[ ] 첨부 이미지의 좋아요 아이콘 영역을 현재 상세 화면에 추가할지 결정한다.
[ ] "좋아요" 상태를 로컬 저장할지 Firebase에 저장할지 결정한다.
[ ] "봤어요" 상태를 로컬 저장할지 Firebase에 저장할지 결정한다.
[ ] 댓글 버튼은 실제 댓글 화면 또는 준비 중 안내 중 하나로 명확히 처리한다.
[ ] 공유 버튼은 share_plus 패키지 사용 여부를 검토한다.
[ ] 로그인하지 않은 사용자의 좋아요·봤어요 동작을 정의한다.
[ ] 액션 영역과 보러가기 버튼의 위치가 겹치지 않게 한다.
[ ] 아이콘 선택 상태의 색상과 기본 상태 색상을 구분한다.

9. 로딩·오류·빈 상태
---------------------
[ ] OTT API 요청 중에는 서비스 아이콘 대신 CircularProgressIndicator를 표시한다.
[ ] 요청이 오래 걸려도 Bottom Sheet가 빈 화면처럼 보이지 않게 한다.
[ ] OTT 데이터가 없을 때 안내 문구를 표시한다.
[ ] 극장 데이터가 없을 때 별도 안내 문구를 표시한다.
[ ] API 오류와 실제 데이터 없음 상태를 구분한다.
[ ] 오류 상태에는 재시도 버튼을 제공한다.
[ ] 영화 id가 잘못된 경우 사용자에게 일반 오류 문구를 표시한다.
[ ] 네트워크가 끊겼을 때 기존 영화 상세 화면은 계속 볼 수 있게 한다.
[ ] 포스터·배경·서비스 로고 이미지 실패 시 placeholder를 표시한다.

10. 순차 검증 시나리오
----------------------
[ ] 홈 화면에서 첫 번째 영화 포스터를 누른다.
[ ] 영화 상세 화면이 정상적으로 열린다.
[ ] 배경 이미지와 제목이 표시된다.
[ ] 예고편 버튼을 누르면 YouTube 예고편이 열린다.
[ ] 보러가기 버튼이 제목·장르 영역 아래에 표시된다.
[ ] 보러가기 버튼을 누르면 Bottom Sheet가 열린다.
[ ] Bottom Sheet 제목이 "어디서 볼까요?"인지 확인한다.
[ ] OTT 탭이 기본 선택되어 있는지 확인한다.
[ ] OTT 서비스 로딩 상태가 표시되는지 확인한다.
[ ] OTT 서비스 데이터가 있으면 아이콘·이름이 표시되는지 확인한다.
[ ] 서비스 하나를 누르면 외부 링크가 열리는지 확인한다.
[ ] OTT 데이터가 없는 영화에서 빈 상태가 자연스럽게 보이는지 확인한다.
[ ] 극장 탭을 누르면 극장 데이터 또는 빈 상태가 표시되는지 확인한다.
[ ] Bottom Sheet를 아래로 밀어 닫을 수 있는지 확인한다.
[ ] 상세 화면으로 돌아왔을 때 스크롤 위치와 데이터가 유지되는지 확인한다.
[ ] 추천 영화 하나를 누른다.
[ ] 새 영화 상세 화면에서도 동일한 보러가기 동작이 반복되는지 확인한다.
[ ] 긴 영화 제목에서 버튼·장르·줄거리가 겹치지 않는지 확인한다.
[ ] 장르가 5개 이상인 영화에서 화면이 깨지지 않는지 확인한다.
[ ] 서비스가 여러 개일 때 가로 스크롤 또는 내부 스크롤이 정상인지 확인한다.
[ ] 세로 화면의 작은 Android 기기에서 Bottom Sheet가 내비게이션 영역과 겹치지 않는지 확인한다.
[ ] 큰 화면과 가로 방향 화면에서 레이아웃이 깨지지 않는지 확인한다.

11. 구현 순서 제안
------------------
[ ] 1단계: TMDB Watch Providers API 응답 구조 확인
[ ] 2단계: WatchProvider 모델과 ApiService 함수 추가
[ ] 3단계: OTT 데이터 파싱 및 KR 지역 필터 구현
[ ] 4단계: Bottom Sheet를 실제 API 없이 임시 데이터로 화면 구성
[ ] 5단계: 임시 데이터를 실제 API Future로 교체

결정이 필요한 사항
------------------
[ ] 극장 탭을 실제 KOBIS API로 구현할지, 예매 링크 중심으로 구현할지 결정
[ ] OTT 링크를 TMDB 링크로 열지, 각 플랫폼의 직접 링크를 만들지 결정
[ ] OTT 로고를 TMDB URL로 표시할지 로컬 assets로 관리할지 결정
[ ] 보러가기 버튼을 장르 아래에 둘지 액션 영역 위에 둘지 결정
[ ] 좋아요·봤어요·댓글·공유 기능을 이번 작업에 포함할지 결정
[ ] 비회원도 OTT 링크를 사용할 수 있도록 할지 결정
[ ] API 요청 실패 시 재시도 횟수와 안내 문구를 결정
[ ] 서비스 제공 정보의 최신성 문제를 사용자에게 어떻게 안내할지 결정

최종 완료 기준
--------------
[ ] 영화 상세에서 보러가기 버튼을 누르면 시청 경로 Bottom Sheet가 열린다.
[ ] OTT 탭에는 대한민국 기준의 실제 제공 서비스만 표시된다.
[ ] 서비스명·아이콘·링크가 API 응답에 맞게 연결된다.
[ ] 극장 탭은 실제 데이터 또는 명확한 빈 상태를 표시한다.
[ ] 로딩·오류·빈 상태가 모두 처리된다.
[ ] 외부 서비스 링크가 Android 실기기에서 정상 실행된다.
[ ] 추천 영화와 목록 보기에서 진입한 상세 화면도 동일하게 작동한다.
[ ] 긴 제목·다수 장르·다수 서비스에서도 UI overflow가 발생하지 않는다.
[ ] 첨부 이미지와 유사한 어두운 Bottom Sheet와 OTT/극장 탭 구조가 구현된다.
[ ] 정적 분석 및 핵심 동작 검증을 완료한다.
