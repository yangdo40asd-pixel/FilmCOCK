FilmCOCK! 3계열 구조도 및 설계 방향성
========================================

문서 목적
---------
첨부된 설계도 예시처럼 FilmCOCK! 영화 추천 앱의 전체 구조를 다음 3개 계열로 정리한다.

1열. API 및 필드 / 백엔드 데이터 흐름
2열. 앱 실행 흐름 / 사용자 이용 순서
3열. UX/UI 화면 명세 / 실제 화면 구성

설계 기준
---------
[ ] 영화 탐색과 개인화 추천을 앱의 핵심 기능으로 둔다.
[ ] TMDB를 영화·인물·예고편·OTT 제공 정보의 주 데이터 소스로 사용한다.
[ ] KOBIS를 국내 박스오피스와 한국 영화인 데이터의 보조 소스로 사용한다.
[ ] Firebase는 로그인 및 향후 사용자 데이터 저장을 담당한다.
[ ] SharedPreferences는 비회원 또는 로컬 환경의 MBTI·취향 상태를 보조 저장한다.
[ ] 화면 계층과 데이터 계층을 분리한다.
[ ] API 실패가 전체 화면 실패로 이어지지 않도록 섹션 단위 오류 처리를 적용한다.
[ ] 한국어 표시를 우선하고, 번역이 없는 콘텐츠는 정해진 fallback 정책을 사용한다.

B. TMDB 영화 API
----------------
[공통 요청 조건]
[ ] base URL: https://api.themoviedb.org/3
[ ] API key: ApiSecrets에서 관리
[ ] 영화 요청 언어: ko-KR
[ ] 국내 시청 정보 국가 코드: KR
[ ] 응답은 UTF-8로 디코딩
[ ] HTTP 오류는 화면에서 처리 가능한 예외로 변환

[영화 목록 API]
[ ] /movie/popular 또는 KOBIS 브릿지 인기 영화
[ ] /movie/now_playing 또는 KOBIS 브릿지 최신 상영 영화
[ ] /movie/upcoming 국내 개봉 예정 영화
[ ] /movie/top_rated 고전·평점 상위 영화
[ ] /discover/movie 장르별 영화
[ ] /movie/{movie_id}/recommendations 유사 추천 영화

C. TMDB 인물 API
----------------
[해외 배우 목록]
[ ] /person/popular page 1~4 조회
[ ] language=ko-KR 요청
[ ] Person.name은 한국어 번역 표시명으로 사용
[ ] Person.originalName은 국적·언어 필터 판단 기준으로 사용
[ ] known_for_department == Acting 조건 적용
[ ] originalName에 한글이 포함된 인물 제외
[ ] 표시명에 일본어·중국어·아랍어·키릴 문자 등이 남는 경우 제외
[ ] TMDB가 한국어 이름을 제공하면 아만다 콜린·제이슨 스타뎀처럼 표시
[ ] 번역이 없고 영어 원문만 있으면 영어로 표시
[ ] profile_path가 없으면 기본 프로필 이미지 표시

[한국 배우 및 감독 목록]
[ ] KOBIS 주간 박스오피스 상위 영화 10개 조회
[ ] KOBIS 영화 상세에서 배우 이름 추출
[ ] KOBIS 영화 상세에서 감독 이름 추출
[ ] 중복 이름 제거
[ ] TMDB /search/person으로 이름 검색
[ ] 검색 결과 첫 번째 인물 매핑
[ ] originalName에 한글 포함 여부 확인
[ ] 한국 배우는 한글 원문 인물만 통과
[ ] 한국 감독은 한글 원문 인물만 통과
[ ] 감독 데이터는 directors 집합으로 별도 관리
[ ] 배우와 감독 목록을 서로 혼합하지 않음
[ ] displayName이 비어 있는 인물은 제외

======================================================================
모듈별 설계 방향성
======================================================================

1. 데이터 계층
---------------
[ ] API 호출은 ApiService에 집중한다.
[ ] 화면 위젯에서 직접 URL을 조립하지 않는다.
[ ] API 응답은 Movie·Person·Video·WatchProvider 모델로 변환한다.
[ ] JSON 필드가 null이어도 모델 생성이 실패하지 않게 한다.
[ ] 한국어 표시값과 원문 필드를 분리한다.
[ ] API별 필터는 서비스 계층에서 처리한다.
[ ] 국가·언어 필터를 요청과 응답 양쪽에서 적용한다.

2. 추천 계층
------------
[ ] MBTI → 장르 ID 매핑을 한 곳에서 관리한다.
[ ] 장르 선택 결과를 향후 추천 점수에 반영한다.
[ ] 인기·최신·장르·유사 영화 추천을 서로 다른 소스로 구분한다.
[ ] 랜덤 추천은 동일한 데이터가 반복되지 않도록 섞는다.
[ ] 추천 결과가 없으면 인기 영화로 fallback한다.

3. 화면 계층
------------
[ ] 반복되는 로딩·오류·빈 상태 위젯을 공통화한다.
[ ] 영화 카드와 인물 카드를 공통 위젯으로 유지한다.
[ ] 상세 화면의 API Future는 영역별로 분리한다.
[ ] 한 영역 실패가 다른 영역 표시를 막지 않게 한다.
[ ] 모든 가로 리스트는 고정 높이를 갖는다.
[ ] 모든 그리드는 작은 화면에서 overflow가 발생하지 않게 한다.

4. 사용자 상태 계층
--------------------
[ ] 인증 여부를 FirebaseAuth.currentUser로 확인한다.
[ ] 비회원은 로컬 저장 중심으로 동작한다.
[ ] 회원은 향후 Firebase Firestore 저장을 검토한다.
[ ] 로그아웃 시 인증 상태와 로컬 상태 정리 정책을 분리한다.
[ ] MBTI 재설정 후 홈·취향 화면이 갱신된다.

5. 오류 및 네트워크 방향성
--------------------------
[ ] 홈 전체를 하나의 Future로 묶지 않는다.
[ ] 영화·인물·추천·시청 정보별로 독립 로딩한다.
[ ] 401 인증 오류는 사용자에게 API 오류로 노출하지 않는다.
[ ] 404 데이터 없음과 네트워크 오류를 구분한다.
[ ] 재시도 버튼을 제공한다.
[ ] 이미지 실패 시 레이아웃 크기를 유지한다.
[ ] API 응답이 늦어도 화면이 점프하지 않게 한다.
