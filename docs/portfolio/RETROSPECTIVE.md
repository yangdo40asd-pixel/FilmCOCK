# 구조 개선 회고

갱신일: 2026-11-17 · 상태: 기술 기록 초안

## 확인한 문제

화면·데이터·외부 API 처리가 섞여 기능 하나를 이해하려면 여러 계층 폴더를 오가야 했다. 문서도 과거 계획과 현재 구현이 함께 있었다. 정적 서비스 기본값은 검사에서 실제 네트워크를 호출할 수 있었다.

## 적용한 개선

기능별 경계와 공용 조회 계약을 만들고 앱 조립부에서 실제 구현을 연결했다. 저장값·API·에셋 경로는 유지하며 실패 복원과 요청 수명을 별도 책임으로 분리했다. 과거 문서는 보관하고 설정·설계·검증·포트폴리오 문서를 나눴다.

## 남은 한계

사용자 실동작 검증, 이미지 권리·정적 데이터 생성 원본, 개인 기여 범위는 아직 확인이 필요하다. SharedPreferences는 트랜잭션 DB가 아니며 실패 복원 역시 저장 장치가 계속 실패하면 보장할 수 없다. 일부 화면 사이 직접 이동과 정적 API 구현은 더 작은 범위에서 개선할 수 있다.

## 후속 판단

실제 검증 결과와 변경 비용을 근거로 계정별 활동 저장, 전체 시작 시간 관찰, 화면 이동 계약, 필요 시 서버 중계를 별도 과제로 판단한다. 이번 구조 변경에 DB·상태관리·모델 제공자 교체를 섞지 않았다.
