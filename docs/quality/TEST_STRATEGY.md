# 검증 전략

갱신일: 2026-11-17 · 상태: 현재 작업 규칙

## 담당 범위

Codex는 코드·설정·문서 수정과 읽기 전용 소스·참조 검토를 담당한다. 앱·에뮬레이터·실기기 실행, 빌드, 자동·수동 테스트, 외부 API 검사는 사용자가 담당한다. 이전에 허용한 정적 자체검사 1회는 이미 사용했으므로 이번 리팩토링에서 다시 실행하지 않는다.

파일 경로·import·Git 차이·문서 링크 확인은 읽기 전용 정리 점검이며 앱 실행 검증이 아니다.

## 현재 검사 구성

- test/unit 아래 activity/auth/chat/core/models/preferences/search로 단위 검사 소스를 분류했다.
- test/helpers의 FakeCatalogRepository와 FixedClock으로 외부 조회·시간을 교체한다.
- 기존 챗봇 검사는 소유자별 anonymous 키와 가짜 조회를 사용한다.
- 저장 실패 복원·동시 댓글 추가·계정별 취향·검색 응답 순서·대화 초기화 검사 소스를 추가했다.
- 검사 소스는 총 13개이며 이번 변경에서 실행하지 않았다. 위젯·통합 검사는 해당 코드가 생길 때 별도 분류하며 빈 폴더를 만들지 않는다.
- 향후 CI 도입은 자동 실행 범위가 합의된 시점에 활성화한다.

## 사용자 실테스트

아래 두 묶음의 체크 상태는 [리팩토링 계획서](../planning/PORTFOLIO_REFACTORING_PLAN.md)에 한 번만 관리한다.

1. 정상 흐름: 로그인·비회원·온보딩, 홈 제목과 추천, 검색, 상세, 활동 동기화, 캘린더, 챗봇.
2. 오류·재실행·출시 회귀: 지연·오프라인·캐시, 계정 변경·저장 이관, LLM 실패, 빠른 입력, 테마·화면 폭·Android 빌드.

## 결과 기록

VALIDATION_LOG에 날짜·커밋·환경·실행자·범위·결과를 남긴다. 과거의 테스트 건수와 결과는 보관 문서의 당시 기록이며 현재 변경분의 통과를 의미하지 않는다.
