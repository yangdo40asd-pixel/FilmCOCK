# 제품 요구사항

갱신일: 2026-11-17 · 상태: 현재 구현 보존 기준

## 제품 목표

영화 탐색, 취향 기반 추천과 개인 활동 기록을 한 앱에서 제공한다. MBTI는 고정 장르 규칙의 입력이며 심리검사나 학습된 추천 모델로 설명하지 않는다.

| ID | 요구사항·보존 조건 |
| --- | --- |
| FR-01 | Firebase 이메일·Google 로그인, 비회원 시작, 로그아웃·탈퇴 경로 유지 |
| FR-02 | 계정별 MBTI·장르 선택 및 명시적 건너뛰기 상태 유지 |
| FR-03 | 시작 화면에서 홈 API 준비, 실패 시 캐시·섹션별 복구 제공 |
| FR-04 | 홈 추천 제목은 MBTI만 표시하고 개인화 갱신 중 기존 목록 유지 |
| FR-05 | 영화·인물·장르 탐색, 자동완성, 검색 기록과 최신 응답 우선 반영 |
| FR-06 | 상세 정보·출연진·예고편·시청 경로·외부 링크 유지 |
| FR-07 | 영화 좋아요·봤어요·댓글·인물 좋아요 변경을 마이페이지에 반영 |
| FR-08 | 관람 날짜별 캘린더, 활동 개수와 등급 진행도 제공 |
| FR-09 | 질문 칩은 규칙 기반, 자유 입력은 설정 시 LLM 우선, 실패 시 규칙 대체 |
| FR-10 | LLM 후보 영화는 TMDB 조회로 확인하며 초기화·화면 종료 시 대화 수명 관리 |
| FR-11 | 홈·취향·챗봇은 같은 MBTI·장르 저장값과 추천 조건을 사용 |
| FR-12 | 테마·이미지 대체 표시·오류 재시도·목록 보기 제공 |

## 비기능 요구

| ID | 기준 |
| --- | --- |
| NFR-01 | 개인 키를 Git에 추가하거나 화면·로그에 출력하지 않음 |
| NFR-02 | 로컬 데이터 키 변경은 명시적 이관 없이는 수행하지 않음 |
| NFR-03 | API 실패로 시작 화면을 무한 대기시키지 않도록 요청 수명 관리 |
| NFR-04 | 외부 조회와 저장 구현을 가짜 구현으로 교체할 수 있는 구조로 개선 |
| NFR-05 | 단위 검사에서 실제 API·유료 LLM 호출에 의존하지 않도록 개선 |
| NFR-06 | 코드 구현과 검증 결과를 구분하고 실행하지 않은 결과를 통과로 기록하지 않음 |

## 범위

현재는 단일 Flutter 패키지다. Firebase 인증과 AI 연동을 사용하지만 활동 기록을 서버 DB에 동기화하지 않는다. 상태관리 라이브러리·DB·LLM 모델 변경, 새로운 기능 추가, 배포 플랫폼 확대는 구조 변경에 묶지 않는다.

기능 표는 코드에서 확인한 보존 기준이다. 모든 항목의 실동작을 이번에 통과 판정한 것은 아니다. 검증 책임은 [검증 전략](../quality/TEST_STRATEGY.md)을 따른다.
